# The Dev Portal in a browser, against agentlab

Playwright drives the portal as a person does, from the Dex sign-in popup to a
chat turn, against a running [agentlab](https://github.com/giantswarm/agentlab).
It complements `agentlab backstage-test`, which checks the same routes and
tokens headlessly. A change to a page ships with the spec that proves it.

## Run

```bash
# once: a Playwright browser
yarn playwright install chromium

# the lab is up (`agentlab up`), or was just reconciled with your dev image
# (`platform.devImages.backstage` + `agentlab platform`)
yarn test:e2e:agentlab

yarn test:e2e:agentlab --grep-invert lifecycle   # the pages only, ~1 min
yarn test:e2e:agentlab -g 'MCP servers'          # one spec
yarn test:e2e:agentlab --headed                  # watch it
AGENTLAB_E2E_ORDER=shuffle yarn test:e2e:agentlab # spec files in a random order
yarn playwright show-report e2e-test-report/agentlab
```

## Portal modes

With `app.portals.agentPlatform` off (the chart's default), Backstage is exactly
the classic portal, without any Agent Platform route. With it on, `/`,
`/sessions`, `/usage`, `/profile`, `/customize/**` and the old
`/agent-platform/**` (redirects only) render the shell and every other route
the classic portal, each linking to the other in a new tab (see
[Portals](../../docs/agent-platform-configuration.md#portals-appportals)).

A lab is in one mode at a time, and `AGENTLAB_PORTAL_MODE` tells the suite
which:

| Project           | Specs                                                                  | Runs when                    |
| ----------------- | ---------------------------------------------------------------------- | ---------------------------- |
| `agentlab`        | the classic portal's (every spec not in `portalModes.ts`)              | always, in either mode       |
| `agentlab-shell`  | the Agent Platform's (`SHELL_SPECS` in `portalModes.ts`), 1440×900     | `AGENTLAB_PORTAL_MODE=shell` |
| `agentlab-mobile` | the Agent Platform on a phone (`MOBILE_SPECS`), 375×812, touch, iOS UA | `AGENTLAB_PORTAL_MODE=shell` |

```bash
# a lab serving the shell: its Backstage with the Agent Platform on, e.g.
# `APP_CONFIG_app_portals_agentPlatform=true` in the chart's extra env (or the
# devImages env in the lab's agentlab.yaml), then:
AGENTLAB_PORTAL_MODE=shell yarn test:e2e:agentlab
AGENTLAB_PORTAL_MODE=shell yarn test:e2e:agentlab --project agentlab-shell
AGENTLAB_PORTAL_MODE=shell yarn test:e2e:agentlab --project agentlab-mobile
```

Before every test the suite reads which portals the lab serves from the
frontend config Backstage injects into its public `index.html`
(`app.portals.agentPlatform`). A lab serving the classic portal only skips
`agentlab-shell` and `agentlab-mobile` with that reason; any other mismatch
with `AGENTLAB_PORTAL_MODE` fails at once, saying what to change.

Model hosting exists only where model-manager answers (`platform.modelManager`
in the lab's `agentlab.yaml`): without it, every Model hosting and serving spec
skips with the reason, read once per worker from muster's server list
(`skipWithoutModelManager` in `model-manager.fixture.ts`) — the ones that stub
model-manager's answers at the browser too, since the portal does not draw the
page for them. The KServe specs also skip without `platform.serving`.

The chart's app-config sets `app.rootRedirect: /agent-platform`, which leads
nowhere in `classic` mode, so run a `classic` lab's Backstage with
`APP_CONFIG_app_rootRedirect=/` too. To switch modes without editing the chart,
give the Backstage pod a ConfigMap's variables
(`backstage.backstage.extraEnvVarsCM` in a `platform.valuesFiles` overlay of the
lab's `agentlab.yaml`, applied once with `agentlab platform`), then change the
ConfigMap and restart the Deployment.

`agentlab-mobile` drives Chromium as a phone (`mobileContextOptions` in
`lab.ts`; `fixtures.ts`' `variant` option applies it to every context of the
worker). Its specs assert phone-only layout and, on every page,
`expectNoHorizontalScroll` (naming the elements past the edge) and
`expectClearOfBottomBar` for the primary action. A new phone check joins
`MOBILE_SPECS`. iOS focus zoom and the soft keyboard are beyond Chromium's
emulation and stay manual checks.

The admin's sign-in checks that the lab serves the expected mode and fails at
once, naming the fix, on a mismatch. A new Agent Platform spec joins
`SHELL_SPECS`.

## The lab users are fixtures

`admin@lab.local`, `dev@lab.local` and `viewer@lab.local` with the password
`password` are throwaway accounts of the lab's static-password Dex connector,
listed in clear text in its `agentlab.yaml`. The suite types that password into
the lab Dex's form. Real people's accounts and real installations' sign-in are
out of this suite's reach.

## Workspaces

`workspaces.fixture.ts` puts workspaces into a known state through the
workspace-manager's own tools, called as a person through the portal's muster
route (`POST /api/muster/call`) with the tokens of that person's signed-in page.
A spec asks for:

- `labWorkspace`: a workspace of the lab's Organization, created as the admin,
  with one source on the lab's GitHub: `agentlab-org/platform-api` by name and
  `agentlab-org/monorepo` by its language (Go) and topic (`monorepo`). The test
  gets it once its first sync succeeded with both repositories in the manifest.
- `refusalWorkspace`: a workspace whose last sync holds the private
  `agentlab-org/platform-infra`, with the developer and the admin connected
  to the lab's GitHub. The developer is a member of the Organization who
  cannot read that repository, so their Session start is refused naming it;
  the admin reads it and is granted.
- `NON_MEMBER`: the viewer. The lab's Organization is the Dex groups
  `platform-admins` and `developers`; `viewers` are outside it.
- `workspaceLab.tools(user)`: the manager's tools as any lab user, on a page of
  their own.
- `workspaceLab.create(kind, sources, repositories)`: a synced workspace of
  this run for a spec that needs one of its own, created the fixtures' way.

Each worker creates its workspaces on first use and deletes them when it ends,
after a failed test too. Their names carry the run's id (`e2e-ws-<run>-…`).
Before every creation the fixtures delete what an earlier run left: an
`e2e-ws-` workspace of another run that started more than three hours ago (by
its run id, else by the workspace's creation). A rerun after an aborted run
starts clean, and a run going on at the same time against the same lab keeps
its workspaces. A leftover that does not go is reported as a warning, not as a
failure of this run.

`workspaces-tab.spec.ts` drives Customize · Workspaces on them, in the
`agentlab-shell` project: the member sees `labWorkspace` with its repository
count, last sync and Sessions, `NON_MEMBER` does not, and a workspace of its
own is deleted through the row menu's confirmation.

What the lab needs:

- Workspaces on (`agentlab configure --workspaces`, then `agentlab platform`),
  on an agentlab that gives the workspace-manager the Organization `lab`, with
  the provider instance `fake` (`--workspaces-provider fake` or `fake,github`).
  Without the workspace-manager, or without `fake`, every workspace spec skips
  with that reason.
- A Backstage whose muster route answers a tool's structured content where the
  tool's text is prose (this repository's main): the workspace-manager answers
  every tool that way. A workspace-manager that muster lists but does not
  serve, or that does not answer `list_providers`, skips the specs too.
- For the refusal, `AGENTLAB_GITHUB_FAKE_URL`: the developer's consent to the
  lab's GitHub is fetched from its loopback port, which the browser reaches,
  unlike its name on the lab domain. Docker publishes the port on IPv4 and
  IPv6; take the first line, `0.0.0.0:<port>`, which this host reaches as
  `127.0.0.1:<port>`. Without it the refusal skips.

Run the workspace specs alone:

```bash
AGENTLAB_GITHUB_FAKE_URL="https://127.0.0.1:$(docker port agentlab-lab-github 8080/tcp | head -1 | cut -d: -f2)" \
  yarn test:e2e:agentlab -g workspaces
```

The smoke test's first-sync time is an annotation in the report.

## Order

Every spec creates what it needs and removes it again, so the files pass in
any order. `AGENTLAB_E2E_ORDER=shuffle` checks that: it runs a project's spec
files in a random order and prints `replay with AGENTLAB_E2E_ORDER=shuffle:<seed>`,
which runs that order again. The worker and its admin page are the default
run's. The order is written as stubs into `.cache/e2e-agentlab-order/`, one
per spec, which import the specs; the report shows each test at its spec's
path (`order.ts`).

## The browser's network

On Linux the suite's Chromium runs in a network namespace of its own
(`netns-chromium.sh`, `browser.ts`). Chromium aborts every in-flight request
with `net::ERR_NETWORK_CHANGED` when any address on the host changes, and on a
lab machine every docker or kind container that starts or stops changes one,
so a full run sharing the host's network fails at a random spec. In the
namespace the browser sees one interface that never changes; `pasta` (from
passt) carries its traffic to the host, loopback ports included, so the lab's
edge, Dex and the kind network are reached as before. Without `unshare` and
`pasta` the browser shares the host's network, with a warning;
`AGENTLAB_E2E_NETNS=0` does so on purpose.

## How it signs in

Each worker signs in as `admin@lab.local` once and keeps that browser context
for all its tests (`fixtures.ts`). A saved `storageState` does not work here:
Dex rotates the refresh token on every silent re-login, so contexts sharing a
cookie sign each other out. Tests that need another user open their own
context (`signInAs`).

## Lab conditions that are not portal bugs

- A Backstage pod roll (a dev-image swap) drops every session, because the lab
  runs an in-memory sqlite. The suite signs in fresh; a browser you keep open
  does not.
- For up to five minutes after a roll, the backend's cached reachability probe
  can call the installation unreachable, so muster cannot connect and the
  wizard offers no installation. The specs fail with that hint; wait or run
  `kubectl -n agent-platform rollout restart deploy/backstage`.
- The lab logs expected console errors (a host model server that is down, a
  `vm-manager` that is not running). The suite fails only on uncaught page
  errors.
- Skill discovery shares GitHub's unauthenticated 60 requests/hour with
  everything else on the machine.
