MCP servers: every server gets a page of its own at `/agent-platform/muster/servers/<server>?installation=<inst>`, and every tool a page beneath it at `…/<server>/tools/<full tool name>`. The server page has the tabs Tools · Overview · Resources · Prompts, plus **Instances** for a server family, with counts in parentheses where muster reports them; Overview is the page's index. Overview carries what the servers page's accordion showed (configuration, authentication, health, live runtime, GitOps provenance); a family's Overview names its instance argument. Tools lists the server's tools by short name with their read-only/destructive markers, filters by `?q=`, lists a family's tools once (including those muster exposes per instance) and shows the sign-in gate when the session is not signed in to the server. Instances lists each family instance with status, last connected and last error, adds a Management cluster column and a coverage line when the instances carry the management-cluster label, and opens an instance's details and sign-in in the side drawer. The server's actions sit in the page header: Edit (or Edit as JSON) and a menu with Deactivate/Activate, Reconnect, Delete and Sign out for a user-registered server, Edit/Remove for a fleet server, Sign in first while one is needed, nothing for a family or for muster. The tool page shows the tool's short and full name, markers, description and input schema, and runs it with the Tool explorer's typed form. muster's core tools have a server page too (`…/servers/muster`). The servers page's rows link to their server page and its tool tags to the tool pages; a server that does not exist on the selected installation says so, with a link back.
