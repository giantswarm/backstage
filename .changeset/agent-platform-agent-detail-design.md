Agent detail page: a failed agent reads **Failed** (no longer "Not accepted", which contradicted its `Accepted=True` condition), and a banner above the tabs says why sessions can't start, naming the root cause, with **Edit agent** for whoever may edit it. A cause in the platform (a missing WorkerPool) points to a platform admin instead. The field the cause is about (Model, Tools or System prompt) is marked. A not-ready agent says sessions can start once it is ready. The Overview's Tools row summarises the toolset in the Agents list's words with a link to the Tools tab, instead of naming the gateway `RemoteMCPServer`. Each fact appears once: the header shows the installation chip and `namespace/name`, and Configuration keeps Model, Tools, Created and Deployed by (Harness, Installation and Namespace rows removed). The Status card no longer repeats the readiness label: a ready agent shows where its sessions run and keeps its conditions and revision behind a closed disclosure, while a failing one lists its conditions in kagent's evaluation order, root cause first and expanded. Revision hashes are shortened and no longer overflow. With no skills, the Skills tab offers **Add skills** (to the edit page) to whoever may edit the agent; with no sessions, the Sessions tab shows **Start a session** instead of an empty table with search and paging.
