Organizations are `Organization` objects with the Agent Platform enabled, identified by their name alone: an organization's page is `/organizations/<installation>/<name>` and its credential form `/organizations/<installation>/<name>/credentials/<operation>`, with no parent namespace. The Organizations page lists each organization one time and offers Create organization, which asks for the name, a display name and the admins (groups and people); the new organization shows at once and says it is not ready until the operator reports it. On an installation whose agent-manager opens pull requests for organizations, the dialog asks how to create it: with a pull request in the installation's repository (selected first), after which it shows the pull request and the organization is created once it is merged, or directly. The choice stays: an organization created with a pull request is changed with pull requests from then on. A person who manages an organization changes its admins on its Members tab; the member form offers the editor and user roles only, and an admin is not removed as a member. Deleting an organization asks for its name. Needs agent-manager with the organization tools on `Organization`. The portal calls agent-manager's tools with the organization's name (`organization`), never its namespace, as agent-manager on `Organization` requires; a write of an installation's model sends no namespace either, so it too needs that agent-manager. A person who reads models namespace by namespace gets the models of an organization they just created or were just added to, with its default preselected, in the New agent form: the portal reads the namespaces of the person's organizations as agent-manager lists them, and the form reads that list again when it opens.
